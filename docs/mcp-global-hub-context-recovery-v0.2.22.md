# v0.2.22 — восстановление контекста локального чата при смене облачного диалога

Дата: 29.10.2026. Основание: практическая приёмка Global Hub v0.2.21.

## Подтверждённые результаты

- После полного завершения browser.exe=0 Windows запустила обычный ChatGPT и Global MCP Apps. Яндекс скрыт через Win32 ShowWindow(SW_HIDE); пользователь работает только в WinForms-чате.
- Первое сообщение eb8754a07f7841e9be2abd51a36bf55b, chat_id 810e129d5501471c9927630b033cf301 доставлено через ui/message target:new и получило ответ АВТОЗАПУСК-21. Статус answered, запись через chat.reply, без ручных действий в браузере.
- Второй запрос bdbfca780e364437bd8624eda5d1fa56 принят через Global Hub, но прежний облачный Thread не поддерживал heartbeat. Global создал ещё один облачный thread. Модель ответила: «Точный текст предыдущего ответа в этом диалоге мне недоступен», не вызвала chat.reply. Локальное сообщение осталось pending с ACK.
- Холодный запуск и первый ответ доказаны. Устойчивое сохранение контекста пока нет.

## Реализация v0.2.22

- ChatUiTools.Pending(discover=true) включает свойство context с максимум пятью последними завершёнными ходами локального chat_id; текст и ответ берутся из JSON сообщений со статусом answered, все поля ограничены по длине. Текущая реплика исключена.
- Global Hub по новому URI ui://chatgpt-mcp-tunnel/hub-relay-v0222 прикладывает историю локального чата к первому ui/message нового облачного thread. Это перенос контекста на уровне приложения; ui/update-model-context старого iframe не переносит его автоматически.
- Инструкция модели усилена обязательным вызовом chat.reply(message_id,reply) перед текстовым ответом.
- Сохранён прежний chat.ui.open(chat_id), число MCP инструментов 56, изменения локальной истории не требуются. Старые тестовые чаты разрешено удалять по указанию владельца.
- Локальные тесты Python+JavaScript подтверждают, что прежний ответ АВТОЗАПУСК-21 попадает в новый ui/message.

## Следующий реальный тест

1. Выпустить v0.2.22, установить проверенным по SHA-256 пакетом.
2. Закрыть браузер целиком, вновь поднять Global из Windows URI, не нажимая ChatGPT.
3. У второго pending тестового сообщения снять только запись ui-forwarded для повторной передачи; первый answered оставить для проверки восстановленной истории.
4. Проверить реальный reply АВТОЗАПУСК-21, статус answered и отсутствие ручных действий в браузере.
5. После успешной приёмки внедрить серверный owner lease Global и автоматический запуск Host Activator непосредственно из Windows-агента.

Важно: невидимый браузерный ChatGPT Host остаётся технической средой выполнения модели; работу без самого процесса браузера это не доказывает.
