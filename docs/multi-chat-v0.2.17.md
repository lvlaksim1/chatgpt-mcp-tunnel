# v0.2.17 — локальные чаты и передача контекста между диалогами MCP Apps

## Новое окно ChatGPT MCP Tunnel — Чат

- Слева: **«＋ Новый чат»** и список чатов **этого компьютера**.
- Можно создавать независимые диалоги и переключаться между ними без удаления предыдущих.
- У каждого чата свой постоянный `chat_id`, история сообщений, тема из первого сообщения, миниатюрный предпросмотр, дата изменения.
- При переключении сохраняются несданный текст и подготовленные вложения в пределах открытого окна.
- Существующие сообщения физически **не переносятся и не перезаписываются**. Для старых записей без `ChatId` автоматически создаётся чат «История до обновления».
- Внизу: реальное время последнего ответа `chat.reply`, без устаревшего сообщения о почасовом планировщике.

## Хранение

- `%LOCALAPPDATA%\ChatGPTMCPAgent\Chat\sessions\<chat-id>.json`: отдельные локальные метаданные каждого чата.
- `%LOCALAPPDATA%\ChatGPTMCPAgent\Chat\active-chat.txt`: выбранный чат текущего компьютера.
- `%LOCALAPPDATA%\ChatGPTMCPAgent\Chat\messages\<message-id>.json`: старые сообщения остаются на месте; новые содержат `ChatId`.
- `%LOCALAPPDATA%\ChatGPTMCPAgent\Chat\ui-routes\<chat-id>.json`: временная информация о связи локального чата и компонента MCP Apps.
- Очереди и вложения сохраняют прежние каталоги.

## MCP Apps

- `chat.ui.open(chat_id)` открывает компонент для конкретного локального чата; без аргумента привязывается к историческому чату для совместимости с предыдущим компонентом.
- `chat.ui.pending(chat_id, discover)`: чтение очереди строго выбранного чата; режим `discover` обнаруживает ожидающий новый локальный чат, не занятый действующим компонентом.
- `chat.ui.ack(message_id, new_chat)`: подтверждение пересылки и отметка первичной инициализации другого диалога.
- Компонент при необходимости отправляет начальное сообщение через `ui/message` c `target: "new"` и просит новый диалог выполнить `chat.ui.open(chat_id=...)`. Для текущего диалога используется `target: "active"`.
- Связанный компонент автоматически начинает проверять свой `chat_id` после получения входного аргумента `chat.ui.open` от ChatGPT через `ui/notifications/tool-input`.
- Компоненты обновляют метки активности, чтобы при исчезновении одной активной связи другой компонент мог обнаружить неподтверждённую очередь.

## Тестирование

- `ChatGptMcpAgent.exe --test-chat-sessions`: создаёт изолированные старые и новые записи, проверяет локальные чаты, сохранение черновиков, переключение, повторное открытие и неизменность старой истории.
- `python tests/test_multichat_routing.py`: проверяет привязку `chat_id`, механизм обнаружения и передачу другому диалогу, подтверждение.
- `node tests/test_multichat_widget.js`: проверяет `ui/message` c `target: "new"` на имитаторе MCP Apps.
- Предыдущие тесты `test_chat_ui_mcp.py`, `test_chat_ui_bridge.js` должны продолжить проходить.
- Изолированный оконный предпросмотр на DOMKAT: создано два чата, отправлены сообщения, переключение по списку вернуло историю выбранного чата.

## Приёмка настоящим ChatGPT

Функция создания нового облачного диалога и автоматического запуска его компонента — **экспериментальная до реального испытания в обычном ChatGPT** после установки v0.2.17 и обновления списка действий. Тестовый сценарий: открыть основной `chat.ui.open`, начать передачу, создать локальный чат кнопкой, отправить сообщение, убедиться в создании нового диалога, вызове `chat.ui.open(chat_id)`, последующем ответе через `chat.reply` и отсутствии смешения историй.

Серверный каталог сообщений DOMKAT не объединяется автоматически с файлами MKATUSHONOK: удалённый многокомпьютерный маршрут требует отдельной приёмки. Часовой планировщик ChatGPT ранее отключён; задача Windows по самовосстановлению туннеля сохраняется.
