# Передача больших файлов через Router Lite (v0.2.9)

Файлы между DOMKAT и подключёнными агентами передаются **по текущему WebSocket/WSS-соединению**, без открытия отдельных портов и без отправки содержимого в чат. Авторизация и проверка TLS применяются как к обычным удалённым командам.

## Управление

Три инструмента MCP:

- `file.transfer.start(source_path, destination_path, source_computer?, destination_computer?, overwrite=false)` — запустить операцию и вернуть `transfer_id`. По умолчанию отсутствующее имя компьютера означает сервер.
- `file.transfer.status(transfer_id?)` — прочитать фактический прогресс (байты, проценты, байты/с, оценка времени, состояние и ошибка). Без ID — последние 20 передач.
- `file.transfer.cancel(transfer_id)` — прервать, сохранив промежуточный файл для продолжения.

На компьютере-сервере: значок ChatGPT MCP Tunnel в трее → **Передача файлов**. Окно показывает список, скорость, проценты, объём, оставшееся время и кнопку прерывания. Окно читает журнал состояния агента `%LOCALAPPDATA%\ChatGptMcpTunnel\Transfers\state.json` и показывает задачи, запущенные через локальный MCP-сервер. Для отмены через окно используется файл-сигнал в `Transfers\Cancel`.

Пример: с MKATUSHONOK на DOMKAT:

```json
{"source_computer":"MKATUSHONOK","source_path":"C:\\Users\\m.katushonok\\Downloads\\MAX.msi","destination_path":"C:\\Users\\Maksim\\Downloads\\MAX.msi"}
```

## Протокол и гарантия целостности

1. Источник сообщает длину и SHA-256.
2. Приёмник создаёт `<имя>.mcp-transfer.part` и `<имя>.mcp-transfer.meta.json`. При совпадении метаданных использует уже принятый объём.
3. Сервер последовательно пересылает блоки по 1 МиБ внутренними командами `inspect/read/prepare/append/finish`. Base64 используется **только внутри WSS**, не в ответе MCP модели. Для одного сообщения установлен предел 16 МиБ.
4. Прогресс обновляется после каждого подтверждённого блока; при временном разрыве соединения операция пробует восстановить передачу.
5. После окончания приёмник проверяет размер и SHA-256 всего промежуточного файла. Только затем он атомарно переименовывается в назначение, а метаданные удаляются.
6. Если конечный файл уже существует, по умолчанию операция отказывает в перезаписи. Для замены требуется `overwrite=true`.

После перезапуска сервера прежний ID может быть недоступен; новая команда start с тем же источником и назначением продолжает сохранённый промежуточный файл. При несовпадающем размере или SHA-256 старый промежуточный файл не перезаписывается.

Для передачи обе стороны должны использовать v0.2.9 или новее. Не передавайте исполняемые файлы из неизвестных источников: проверка SHA-256 подтверждает идентичность источнику, а не безопасность или подлинность издателя.

## Проверка

`python tests/test_file_transfer.py`: реальный Router Lite + имитированный агент на отдельном WebSocket-подключении; проверяет 15 МБ вверх и вниз, перезапись, отмену, продолжение и 90 МБ с SHA-256. Выполняется в проверках GitHub Actions перед сборкой установщиков. Для подтверждения через Интернет требуется обновить оба компьютера и провести физическую передачу.
