**Кому:** постоянному менеджеру `manager_id=project-manager` версии 2.1.0 в `lvlaksim1/chatgpt-mcp-tunnel`. Это продолжение того же менеджера в новом runtime/чате, а не новый агент. **Источник:** последовательность прямых поручений владельца, наблюдений и инструментальных результатов 29–30 октября 2026 года. Читать вместе с `.context/decisions/operating-model-2026-10-30.md`.

## Хронология значимых решений и выполненных действий

1. **Обычный чат, а не Work.** В предыдущих испытаниях `chat.ui.open` создавал обычные ChatGPT-диалоги, а более поздний Global Hub через `ui/message target:new` открывал Work/Astra. Выполнено разделение в коде v0.2.24/25: Global — наблюдатель без отправки; `chat.bootstrap.open` — отдельный инструмент для запуска в существующем обычном `/c`. Были локальные тесты, но реальная end-to-end гарантия нормального режима новых диалогов не должна объявляться доказанной без отдельной приёмки. Не использовать Work/Codex/OpenAI API для транспортного чата.
2. **Индикация управления и СТОП.** Владелец потребовал постоянно видимое локальное окошко справа внизу над часами Windows при действиях модели, короткую историю, явное завершение и аварийную кнопку STOP. STOP должен действовать локально на целевом ПК, при потере связи и после рестарта, не ждать GUI pacing, блокировать новые команды, давать локальное ручное возобновление. Не показывать токены, пароли, содержимое файлов и полные shell-команды.
3. **GUI-пауза и замеры.** Владелец определил около **1 сек между GUI-действиями**; чтение UI, получение экрана, PowerShell/CMD, файлы и процессы не требуют паузы. Первые замеры MCP DOMKAT: bridge_ping ~1,1 сек, window.list ~1,7 сек, screen.info ~0,7 сек, UIA.tree ~2,8 сек. Долгие паузы 10–15 секунд во многом обусловлены дополнительными модельными циклами.
4. **v0.2.25.** Реализованы `ControlState` (общий локальный gate для агента/исполнителя), `ControlOverlay`, `desktop.batch` с локальным GUI pacing, STOP-guards, persistent STA PowerShell UI Automation worker, обработка некоторых CLI/transfer отмен. Локальные тесты и CI успешны. Но при реальном тесте владелец не увидел кнопку/окно: класс формы был, а основной `TrayContext` её не создавал. Пройденный selftest формы не доказывал реальную индикацию.
5. **v0.2.26.** Исправлено подключение `ControlOverlay` к главному агенту, `Poll` в существующем таймере и тест нативной видимости HWND, иначе WinForms `Visible=true` мог вводить в заблуждение. Повторный локальный UIA worker дал ~339 мс первый вызов и ~9 мс второй локальный, не измерение полного цикла модели. После установки пользователь подтвердил, что уведомление появляется.
6. **Локальная разработка вместо облачной.** Владелец предложил перенести саму разработку на компьютер для скорости. Согласована **`D:\Dev`** (не `D:\Development`), создан локальный Git-клон `D:\Dev\ChatGPT-MCP-Tunnel` на DOMKAT с `main`/историей/origin. Старая `D:\ChatGPT-MCP-Tunnel`, рабочая установка `D:\ChatGPTMCPAgent`, посторонние неотслеживаемые файлы сохранены нетронутыми.
7. **Подробные подписи v0.2.27.** Владелец сообщил, что «Выполнение команды» слишком малоинформативно. Введены безопасные категории `ControlActivityLabels` для Git, исходников, .NET, тестов, процессов, UIA, обновлений и др.; `shell.exec` классифицирует действия, с ограниченным `activity`; секреты/текст команд не хранятся. Коммит `311b33c`; локальные тесты прошли.
8. **Нарушение договорённости про GitHub.** Ассистент всё-таки запустил и опрашивал GitHub Actions; пользователь показал это и указал: **«мы же договорились что гитхаб только как хранилище»**. Ассистент признал ошибку. Релизный run `40975526773` отменён/force-cancel, все три workflow (`agent-installer-release.yml`, `mcp-smoke.yml`, `repository-storage.yml`) перешли в `disabled_manually`. Этот прямой запрет **сильнее** старых менеджерских планов CI/Actions.
9. **Локальный выпуск v0.2.27.** На DOMKAT найдены Inno Setup 6.7.3, .NET 8 SDK, Python 3, официальный `tunnel-client.exe` v0.0.18 в рабочем приложении. Созданы `scripts/Build-LocalRelease.ps1` и `docs/LOCAL-DEVELOPMENT.md`, коммит `2f7fe42`. Локально выпущены Agent/Runtime, прошли WinForms/MCP тесты, Inno full/update, SHA256 manifest. Файлы `.tools/local-release/v0.2.27/dist` напрямую опубликованы GitHub Release `v0.2.27` без Actions.
10. **Автообновление DOMKAT по прямой просьбе.** Владелец распорядился автоматически обновить. Проверен SHA-256; отдельное локальное одноразовое задание Windows `ChatGPTMCP_LocalUpdate_0_2_27` штатно закрыло агент, отпустило файлы и установило `v0.2.27`. Установленная версия `0.2.27+311b33c...`, MCP bridge_ping, агент, tunnel-client и runtime проверены. Установщик Inno завершился успешно и сохранил конфигурацию. **Урок:** внешний `Start-Process -Wait` продолжал ждать потомка-tray после завершения установки; ожидающий PowerShell пришлось остановить, одноразовую задачу удалить. Для следующего апдейта ждать конкретный процесс по `WaitForExit(timeout)` и/или проверять итоговый файл/версию, не ожидать всю цепочку потомков.
11. **Вопросительные знаки в UI.** Пользователь показал скриншоты «????»: пункт меню «Индикатор управления / СТОП» и 4 описания опасных команд (удалить файлы, завершить процессы, разделы диска, системные параметры). Проверка исходников показала *буквальные знаки вопроса в строках*, а не сбой Windows-шрифтов. Исправление начато в `D:\Dev`: Unicode-строки, тесты и bump `v0.2.28`. Эти правки пока НЕ закоммичены и НЕ выпущены. В четырёх файлах: `src/ChatGptMcpAgent/Program.cs`, `src/Shared/ControlActivityLabels.cs`, `src/ChatGptMcpAgent/ControlTests.cs`, `src/ChatGptMcpAgent/ChatGptMcpAgent.csproj`. Первая сборка прошла, было предупреждение CS0162 (проверить/убрать). Никаких reset/clean/перезаписей этих изменений.
12. **Снова про производительность — последний запрос владельца.** Пользователь заметил, что компьютерные операции быстры, а паузы *между отдельными обращениями* огромны; приказал **сначала продумывать серию действий и выполнять её целиком**, а не между каждыми двумя микродействиями возвращаться к модели. Решение: локальный пакетный сценарий для связанных операций (правки → сборка → тесты → итог), fail-fast/проверки и затем один содержательный отчёт; не спамить проверками CI или статусов. GUI по-прежнему ~1 сек между изменениями; CLI без фиксированной паузы; моделирование нужно на развилках.
13. **Состояния индикатора.** Пользователю и ассистенту стало понятно, что сообщение «Управление завершено» после конкретной операции бывает ложным, когда модель ещё решает следующий шаг. Для следующей реализации предложены «Выполняю действия на компьютере», «Ожидание решения модели» и «Задача действительно завершена». Это пока **обсуждённое улучшение, не готовый протокол**. При его разработке нельзя выводить «завершено» лишь из тайм-аута отсутствия вызовов, нужен сигнал/механизм этапа.
14. **Роль менеджера.** Владелец прямо попросил восстановить того же менеджера проекта и донести до него разговор. Зафиксировать решения в `.context` и `docs`, обновить текущие планы/намерения и единый integrity seal; не менять manager_id, Contract, Core-версию или рабочую установленную программу в рамках восстановления.
