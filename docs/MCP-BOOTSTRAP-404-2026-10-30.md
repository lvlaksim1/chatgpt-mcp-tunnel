# MCP Apps bootstrap: ошибка HTTP 404 из-за устаревшей регистрации

Дата диагностики: 30 октября 2026, DOMKAT, Яндекс Браузер, обычный ChatGPT.

## Подтверждённая причина

При вызове `chat.bootstrap.open` инструмент успешно выполняется, однако ChatGPT не может открыть компонент. В DevTools → Network после повторной попытки обнаружен:

- `GET /backend-api/ecosystem/widget`
- `action_name=chat.bootstrap.open`
- `template_pointer=ui://chatgpt-mcp-tunnel/chat-bootstrap-v0224`
- Ответ: HTTP **404**, JSON `{"detail":"HTML asset not found"}`.

Установленный на момент проверки агент `v0.2.29` объявлял только `ui://chatgpt-mcp-tunnel/chat-bootstrap-v0229`, локальный `resources/read` для v0229 работал. Это рассинхронизация сохранённого определения MCP-инструмента/виджета в ChatGPT и новой версии сервера. Текста сообщения или содержимого чата в диагностический отчёт не копировали.

Отдельно в консоли обнаруживались React minified error 418 и запрет исполнения inline-script по CSP, но эти сообщения **не доказывают**, что они вызвали именно HTTP 404; первичная блокировка виджета — отсутствие HTML asset v0224.

## Локальное исправление, кандидат v0.2.30

В `ChatLifecycleTools` добавлены два обратносуместимых MCP Resources:

- `ui://chatgpt-mcp-tunnel/chat-bootstrap-v0224`
- `ui://chatgpt-mcp-tunnel/chat-bootstrap-v0225`

Оба адреса читают **текущую** защищённую реализацию `ChatBootstrapApp.html`, в которой Global/Work-контекст не запускает пересылку, а неизвестный контекст требует подтверждения пользователя. Новое `chat-bootstrap-v0229` остаётся основным. Локальный `resources/read` проверяет байтовое совпадение HTML для трёх URI; опубликованный ChatGPT snapshot может потребовать отдельной ручной актуализации/переопубликования даже после установки, поскольку серверный ответ 404 формирует экосистема ChatGPT, а не .NET-агент.

Обновлённый индикатор также показывает реальную версию агента из `Application.ProductVersion`. GitHub Actions не задействованы.

## Ограничения приёмки

- Успешный MCP `resources/read` по старому URI не является доказательством, что хост обновил свой сохранённый widget asset.
- Фактическое создание нового **обычного** чата ChatGPT не подтверждено до живой проверки.
- Из старой очереди сообщений ничего не удалено и не переслано; запускать автоматическую пересылку без изоляции ранее ожидавших элементов нельзя.
- Открытие страницы управления зарегистрированным плагином из ChatGPT через браузер было остановлено системой безопасности инструментов; настройки/разрешения плагина не изменялись. Не обходить запрет автоматизацией.
- Контекст разработки: `D:\Dev\ChatGPT-MCP-Tunnel`; GitHub только хранение релиза и исходников, никаких GitHub Actions.

Сведения о замороженных снимках конфигурации MCP-плагинов: https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt
