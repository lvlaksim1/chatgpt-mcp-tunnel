## Новая реализация v0.2.21

- chat.hub.open (Global) получает новый versioned URI ui://chatgpt-mcp-tunnel/hub-relay-v0221 и отдельный ресурс ChatGlobalHubApp.html. Thread диагностический ресурс lifecycle-thread-v0220 не меняется, существующий chat.ui.open(chat_id) и ChatRelayApp.html не меняются.
- Global Hub при ui/initialize автоматически запускает опрос app-only chat.ui.pending(chat_id=LegacyId,discover=true). Никакой кнопки «Начать передачу».
- Найденное сообщение нового локального чата передаётся через ui/message с OpenAI extension target=new,send=true. Первая отправка включает chat_id и инструкцию модели открыть существующий chat.ui.open(chat_id) и записать ответ через chat.reply(message_id,reply).
- Только после принятия хостом ui/message вызывается chat.ui.ack(message_id,new_chat=true), чтобы предотвращать повторную отправку по обычному маршруту.
- После перехода в новый ChatGPT thread уже существующий ChatRelayApp.html с chat_id автоматически активирует приём следующей очереди. Global Hub не забирает сообщения из чатов с живой привязкой маршрута.
- Hub поддерживает heartbeat, реагирует на host-context-changed, видимость и teardown; технические логи не сохраняют тексты переписки/токены/полные URL.
- При ошибке отправки сообщение остаётся в локальной очереди; Global повторяет попытку через 7 секунд.

## Следующая практическая проверка

1. Выпустить и установить v0.2.21, обновить инструменты плагина.
2. Закрыть все процессы Яндекс Браузера. Без открытия браузера руками запустить Global из Windows URL.
3. Открыть локальный чат ChatGPT MCP Tunnel; создать новую беседу и отправить уникальное тестовое сообщение. В браузере ничего не нажимать и не печатать.
4. Проверить в журнале новый экземпляр Global, hub-forwarded, ui-forwarded, привязку chat.ui.open(chat_id) и статус answered с реальным содержимым reply.
5. Написать второе сообщение в тот же локальный чат; проверить ответ без ручной переинициализации.
6. При необходимости проверить минимизированный браузер (фонового процесса достаточно, но пользовательский интерфейс браузера не должен быть нужен).
7. Дальнейшее развитие: устойчивые аренды Global (защита от двух параллельных экземпляров), управление запуском URI из Windows агента, локальная капсула контекста. Не строить специальные схемы миграции/резервных копий старых тестовых чатов по явной просьбе владельца.

Всё остаётся на одном MCP Tunnel, без Work, Codex, Sign in with ChatGPT, отдельного API и облачного планировщика.
