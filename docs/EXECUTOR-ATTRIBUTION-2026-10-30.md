# Исполнитель в индикаторе управления — 30.10.2026

Решение владельца: окно ChatGPT MCP Tunnel должно показывать **«Исполнитель»** для каждой операции на ПК.

## Передача исполнителя

Каждый из Windows MCP-инструментов (`shell.exec`, `fs.*`, `desktop.*`, `process.*`, `system.info`), `desktop.batch` и `file.transfer.start` принимает **необязательное поле `executor`**:

| Значение аргумента | Строка в уведомлении |
|---|---|
| отсутствует, null, `chatgpt` или неизвестное значение | ChatGPT |
| `project-manager` | Менеджер проекта |
| `supervisor` | Супервизор |
| `persona:Старший разработчик` | Старший разработчик |

Для персонализированного чата вызывающая модель **должна явно указывать** `executor` при каждом действии. Для обычного чата поле можно опускать. Не следует устанавливать глобального исполнителя на весь компьютер/процесс: это неправильно подпишет команды параллельных бесед.

Значение ограничено известными идентификаторами либо коротким безопасным персонализированным названием. Аргументы shell, пароль, токен, URL, путь и содержимое файлов не должны становиться названием исполнителя. Неизвестное/небезопасное значение преобразуется в `chatgpt`.

**Важное ограничение:** текущий MCP Host не сообщает проверенную идентичность «какой чат/агент вызвал этот инструмент». Поэтому `executor` — *заявленная отправителем подпись операции*, а **не криптографически доказанная идентичность и не авторизация**. STOP, сетевые разрешения и аудит полномочий не должны опираться на эту подпись.

## Маршрутизация

- Подпись передаётся непосредственно в каждом вызове, включая Router Lite на удалённый ПК.
- `desktop.batch` распространяет одну подпись на все вложенные разрешённые шаги и запрещает переопределять `executor` в аргументах отдельного шага.
- `file.transfer.start` сохраняет подпись для фоновой передачи и передаёт её для `inspect/read/prepare/append/finish` на стороне источника и назначения.
- В журнале `ControlState` хранится только нормализованный идентификатор, не полный текст пользовательской команды.
- Индикатор выбирает исполнителя последней активной, иначе последней завершённой операции; он не переиспользует личность предыдущего чата для нового вызова.

## Примеры

```json
{"command":"dotnet build", "computer":"DOMKAT", "executor":"project-manager"}
```

```json
{"steps_json":"[{\"tool\":\"desktop.window.list\",\"arguments\":{}}]", "computer":"MKATUSHONOK", "executor":"supervisor"}
```

После обновления установленного туннеля может потребоваться обновить каталог инструментов плагина в обычном ChatGPT, чтобы новое необязательное поле было видно модели. GitHub Actions для выпуска не используются.
