# ChatGPT MCP Tunnel v0.2.23 — автоматический запуск Global Hub из Windows

Дата: 30.10.2026. Назначение: убрать ручное открытие ChatGPT и deep link из сценария локального чата.

## Что уже подтверждено в реальном испытании

1. На DOMKAT полностью остановлены все процессы Яндекс Браузера, оставлен работающим единственный MCP Tunnel.
2. Системное открытие глобальной точки входа ChatGPT автоматически запустило браузер и заново создало iframe Global Hub.
3. Global Hub обработал сообщение из нового локального чата, создал обычный ChatGPT thread через ui/message target:new.
4. Ответ ХОЛОДНЫЙ-УСПЕХ был сохранён в исходном локальном чате через chat.reply; маршрут стал ready.
5. Проверка второго сообщения выявила возможный сценарий без chat.reply. Отдельное изменение v0.2.22 добавило передачу локального контекста для восстановления при новом thread. Это не заменяет последующую проверку надёжности подтверждения ответа.

## Изменения v0.2.23

- Добавлен ChatHostActivator в Windows ChatGptMcpAgent.
- Мониторинг встроен в существующий TrayContext и не создаёт второй туннель, сервис или планировщик ChatGPT.
- Только серверная роль (для текущей архитектуры DOMKAT).
- Каждые 12 секунд проверяются:
  - наличие нового локального сообщения со статусом pending, ещё не переданного MCP Apps;
  - последнее событие heartbeat от Global Hub в журнале жизненного цикла;
  - минимальный интервал между повторными попытками запуска.
- При отсутствии живого Global Hub и наличии ожидающей очереди Windows самостоятельно открывает заранее подтверждённый Global entrypoint. Сам пользователь не выполняет действий в браузере.
- Период активности heartbeat: 75 секунд; задержка между попытками запуска: 120 секунд.
- Адрес конкретной установленной копии плагина сохраняется исключительно в пользовательском файле %LOCALAPPDATA%\ChatGPTMCPAgent\Chat\hub-entrypoint.url. Аккаунтно-зависимый идентификатор плагина не публикуется в исходном коде.
- URL строго проверяется: HTTPS, ровно chatgpt.com, путь /mcp-app/asdk_app_.../chat.hub.open, без query/fragment/учётных данных.
- При запуске запрашивается минимизированное окно, но это не гарантия отсутствия окна, если браузер уже работает; отдельное испытание необходимо.
- Повторная доставка ответов по уже отмеченным ui-forwarded сообщениям не выполняется автоматически, чтобы не создавать дубли при неизвестном результате первой отправки.

## Проверки

- dotnet build ChatGptMcpAgent и ChatGptMcpTunnel -c Release --no-restore: 0 ошибок, 0 предупреждений.
- ChatGptMcpAgent.exe --test-host-activator проверяет URL, свежесть heartbeat, очередь, дедупликацию по ui-forwarded и время охлаждения, не открывая браузер.
- Windows GitHub Actions запускает эту проверку перед сборкой установщиков.

## Приёмка на DOMKAT

1. Сначала собрать и выпустить 0.2.23, установить проверенный SHA-256 обновления.
2. Создать hub-entrypoint.url с адресом глобального приложения, реально ранее открытого из Windows на DOMKAT (не включать этот адрес в публичный репозиторий).
3. Полностью закрыть Яндекс Браузер и убедиться, что browser.exe = 0, а ChatGptMcpAgent и readyz работают.
4. Открыть только локальное окно ChatGPT MCP Tunnel, создать новый чат и отправить тестовое сообщение.
5. Проверить, что TrayContext инициирует запуск Windows Host автоматически, Global Hub получает ui-initialize, выполняется ui/message target:new, затем chat.ui.open/chat.reply и ответ отображается в локальном чате.
6. Отправить второе сообщение в том же чате и проверить сохранение контекста, доставку и статус answered. Если reply отсутствует, зафиксировать отдельную точку отказа, не объявлять полную приёмку.
7. Проверить повторный запуск после закрытия браузера без ручных ссылок, затем контролируемую перезагрузку Windows.

## Граница результата

Это механизм автоматического запуска обычного ChatGPT Host из Windows. На текущем этапе для генерации используется браузерный процесс, который открывается программой. Полная независимость от любого браузерного движка не заявляется. Пользовательский интерфейс по-прежнему только в окне ChatGPT MCP Tunnel, Work/Codex/API не используются.
