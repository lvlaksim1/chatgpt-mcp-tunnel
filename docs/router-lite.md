# Router Lite — один MCP-туннель, несколько компьютеров

Статус: **этап 1 реализован и локально проверен 28.10.2026**. На втором физическом ПК испытаний ещё не было.

## Принятая архитектура

`ChatGPT → OpenAI Secure MCP Tunnel → единственный MCP-сервер/маршрутизатор DOMKAT → локальный исполнитель или удалённый агент`.

Один исполняемый файл `ChatGptMcpTunnel.dll` работает в двух режимах:
- по умолчанию — основной MCP-сервер через `stdio`; при явном включении параллельно принимает агентов;
- `--agent` — подключается к маршрутизатору по WebSocket и выполняет адресованные команды.

Локальная маршрутизация остаётся поведением по умолчанию. Глобальные 17 инструментов GitHub остаются на основном узле.

## Текущие возможности

- Существующие 41 инструмент доступны без изменения прежних параметров.
- Добавлен `computers.list` — показывает локальный ПК и активные соединения (42 инструмента всего).
- `system.info` получил необязательный `computer`; если имя отсутствует или соответствует локальному компьютеру, выполняется прежняя локальная реализация.
- Агенты подключаются исходящим соединением и подтверждают общий секрет. Конфликт имён компьютеров отклоняется.
- Идентификаторы запросов, ожидание ответа (40 с), сообщения об отключении и неизвестном компьютере.
- Отправка и приём ограничены 16 МиБ; при неопределённом результате выполнения команда не отправляется повторно.
- Новый сетевой слушатель выключен по умолчанию; работающий туннель DOMKAT не изменён.

**Не реализовано:** удалённое выполнение остальных 22 инструментов Windows, хранение индивидуальных ключей, графический список компьютеров, установка на второй физический ПК. Они входят в следующие этапы.

## Проверка без второго компьютера

Собрать из корня репозитория:

```powershell
dotnet build src/ChatGptMcpTunnel/ChatGptMcpTunnel.csproj -c Release
python tests/test_router_lite.py
```

Тест запускает два отдельных процесса из одной сборки, временно создаёт случайный ключ, получает список MCP-инструментов, подключает тестового агента, вызывает удалённый `system.info`, проверяет отказ неизвестному компьютеру и отключение агента. Не меняет живой туннель и пользовательские документы.

При работающем официальном `tunnel-client` для теста можно собрать во временный каталог и передать `CHATGPT_MCP_TEST_DLL`, чтобы не перезаписывать загруженную сборку.

## Пример настройки (после тестирования на отдельном ПК)

На **маршрутизаторе DOMKAT** задать в окружении процесса:

```powershell
$env:CHATGPT_MCP_ROUTER_ENABLED = '1'
$env:CHATGPT_MCP_AGENT_TOKEN = '<случайный длинный секрет>'
$env:CHATGPT_MCP_ROUTER_LISTEN = 'http://127.0.0.1:55201'
dotnet src/ChatGptMcpTunnel/bin/Release/net8.0/ChatGptMcpTunnel.dll
```

На втором ПК (только в защищённой частной сети или через WSS/TLS):

```powershell
$env:CHATGPT_MCP_AGENT_TOKEN = '<тот же секрет>'
$env:CHATGPT_MCP_COMPUTER_ID = 'PC-2'
$env:CHATGPT_MCP_ROUTER_URL = 'wss://router.example/agent'
dotnet ChatGptMcpTunnel.dll --agent
```

По умолчанию адрес слушателя `127.0.0.1`, он не принимает удалённые соединения. Для другого компьютера нужен доступный защищённый адрес (например, частный адрес Tailscale через сетевое шифрование или обратный прокси с TLS) и соответствующая настройка `CHATGPT_MCP_ROUTER_LISTEN`. Не выставлять порт с обычным `ws://` в публичный интернет: заголовок с ключом не защищён без TLS/частной сети. Не сохранять секреты в репозиторий.

**Текущий режим агента предназначен для испытаний:** при потере связи повторное соединение выполняется автоматически; отсутствует постоянное хранение ключей и развёртывание службой Windows.
