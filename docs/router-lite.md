# Router Lite — один MCP-туннель для нескольких компьютеров

## Фактическая топология DOMKAT — MKATUSHONOK (поправка 28.10.2026)
DOMKAT и MKATUSHONOK находятся **в разных локальных сетях**. Адрес DOMKAT `192.168.0.3:55201` — адрес его локального интерфейса, поэтому ранее предлагавшееся прямое подключение MKATUSHONOK к этому адресу без дополнительного маршрута ошибочно. В текущем проекте один OpenAI MCP Tunnel обеспечивает канал ChatGPT → DOMKAT, но не предоставляет автоматически обратного общедоступного адреса для клиентов Router Lite.
**Транспорт не выбран владельцем**. Минимальное решение для проверки — зашифрованная виртуальная сеть (например, Tailscale/WireGuard): обе машины получают маршрутизируемые внутри VPN адреса; Router Lite должен слушать адрес DOMKAT на защищённом виртуальном интерфейсе. Альтернатива — отдельный защищённый WSS-маршрут, но это другая инфраструктура.
Важно: клиентская проверка `AgentStorage.ValidateRouter` принимает `ws://100.64.0.0/10` для Tailscale, а серверный диалог позволяет привязку к IPv4, назначенному локальному сетевому интерфейсу. Однако кнопка `LanFirewall.LocalNetwork` работает только с диапазонами RFC1918 (10/8, 172.16/12, 192.168/16) и не поддерживает Tailscale-адреса 100.64.0.0/10. Для VPN-схемы необходима отдельная безопасная настройка брандмауэра, проверка привязки к интерфейсу и приёмочные испытания.
Не выполнять автоматическую установку VPN, настройку публичного порта, изменение Tunnel ID/секретов или серверного адреса до согласования архитектуры с владельцем. Реальное межсетевое соединение MKATUSHONOK пока **не подтверждено**.


Статус 28.10.2026: **этапы 1–3 разработаны и проверены между отдельными процессами на DOMKAT**. Проверка на втором физическом компьютере ещё предстоит. Действующий OpenAI tunnel-client и пользовательская установка не перезапускались.

## Архитектура

`ChatGPT → один OpenAI Secure MCP Tunnel → MCP Router Lite на DOMKAT → локальный инструмент или именованный агент Windows`.

Одна сборка `ChatGptMcpTunnel.dll` поддерживает два режима:
- Обычный `stdio` MCP с 42 инструментами; когда `CHATGPT_MCP_ROUTER_ENABLED=1`, дополнительно запускает WebSocket-приёмник агентов.
- `--agent`: исходящее подключение к маршрутизатору с постоянным именем компьютера. Агент выполняет только разрешённые Windows-инструменты; GitHub-инструменты остаются на основном узле.

Используется один файл `RouterLite.cs`; нет базы данных, брокера сообщений, отдельного репозитория или обязательного облачного сервера.

## Инструменты и выбор компьютера

Все исходные 41 инструмента сохранены; `computers.list` добавлен как 42-й. **Все 23 инструмента Windows** (8 системных/файловых/процессов + 15 мультимедиа/UIA) получили необязательный параметр `computer`. Если его нет или он совпадает с локальным именем, команда исполняется непосредственно как прежде. Если указан другой компьютер, запрос идёт исключительно ему. Неизвестный/отключённый компьютер вызывает ошибку; переноса команды на DOMKAT не происходит.

Графические результаты MCP остаются блоками `text` и `image`; PNG передаётся без двойного кодирования. На каждом агенте команды управления рабочим столом последовательно упорядочены, системные вызовы могут выполняться параллельно.

## Протокол и устойчивость

- Постоянное WebSocket-соединение, сопоставление запросов/ответов по случайным уникальным идентификаторам.
- Переподключение агента после потери маршрутизатора (проверено перезапуском тестового маршрутизатора).
- Общий секрет подключения (первоначальный минимальный режим); неверный секрет и повтор имени активного агента отклоняются.
- Ошибки выполнения, отсутствие компьютера и разрывы канала возвращаются клиенту; команды с неясным исходом не отправляются заново.
- Лимит сообщения 16 МиБ: слишком большой ответ возвращает ошибку с предложением уменьшить размер.
- Ожидание ответа по умолчанию 45 с; для `shell.exec` учитывается заданный предел выполнения команды (до 3600 с) с запасом.
- Отдельная очередь графических действий на каждый агент. Для GUI требуется активный пользовательский сеанс Windows.

## Сборка и испытания на одном DOMKAT

```powershell
dotnet build src/ChatGptMcpTunnel/ChatGptMcpTunnel.csproj -c Release -o .tools/router-lite-build
$env:CHATGPT_MCP_TEST_DLL='D:\ChatGPT-MCP-Tunnel\.tools\router-lite-build\ChatGptMcpTunnel.dll'
python tests/test_mcp_stdio.py
python tests/test_router_lite.py
python tests/test_router_reconnect.py
python tests/test_windows_tools.py
python tests/test_gui_input_tk.py
python tests/test_windows_uia.py
python tests/test_winforms_uia_compat.py
python tests/test_uia_real_apps.py
```

Испытания успешно выполнены 28.10.2026. Они охватывают: 42 инструмента и 23 параметра `computer`, текст/PNG, файлы/PowerShell/процессы, отдельное тестовое WPF-окно, мышь/клавиатуру, UIA, параллельные запросы, неверные ключи и конфликт имён, отключение и восстановление связи. Исходные локальные Windows/GUI/UIA тесты пройдены на отдельной сборке. Контроль сетевой работы между физически отдельными ПК **не проводился**.

## Ручная настройка для дальнейшего этапа

На маршрутизаторе DOMKAT задать переменные окружения процесса:

```powershell
$env:CHATGPT_MCP_ROUTER_ENABLED = '1'
$env:CHATGPT_MCP_AGENT_TOKEN = '<длинный случайный секрет>'
$env:CHATGPT_MCP_ROUTER_LISTEN = 'http://127.0.0.1:55201'
dotnet .tools/router-lite-build/ChatGptMcpTunnel.dll
```

На агенте (в отдельной тестовой сети):

```powershell
$env:CHATGPT_MCP_AGENT_TOKEN = '<тот же секрет>'
$env:CHATGPT_MCP_COMPUTER_ID = 'PC-2'
$env:CHATGPT_MCP_ROUTER_URL = 'ws://127.0.0.1:55201/agent'
dotnet ChatGptMcpTunnel.dll --agent
```

Приведённые адреса `127.0.0.1` показывают **тест на одном компьютере**. Для другого ПК настройте защищённый доступный адрес. Не размещайте обычный `ws://` и заголовок с секретом в публичной сети; используйте шифрованную частную сеть (например, Tailscale) либо TLS/`wss://`. Автоматическая установка, хранение индивидуальных ключей, автозапуск агентов и обновление текущего туннеля относятся к следующему этапу.
