# ChatGPT MCP Tunnel v0.2.35 — исправление маршрутизации чатов

**Цель:** существующий локальный чат продолжает свой обычный диалог ChatGPT, новый облачный диалог создаётся только для явно созданного локального чата.

- `ChatSessionStore.Create()` записывает `CreateCloudThread=true`; старые сессии без поля остаются существующими и не получают этот флаг.
- Привязанный MCP-компонент читает очередь только своего `chat_id` и отправляет её в `ui/message target:active`.
- Поиск других локальных чатов допускает только явно созданные новые сессии. При обнаружении создаётся атомарная блокировка `creating`, чтобы несколько компонентов не создали один и тот же облачный диалог.
- После первого сообщения нового чата ассистенту предлагается открыть `chat.ui.open(chat_id=...)` непосредственно в созданном диалоге. Все последующие сообщения требуют этой привязки.
- Пользовательский текст передаётся без подстановки всей предыдущей истории, диагностического JSON, заголовков и длинных инструкций. Для возврата ответа сохраняется минимальная служебная метка `chat.reply(message_id,reply)`.
- Новый ресурс `relay-v0235` обновляет кешированный интерфейс; старые URL ресурсов сохранены как совместимые псевдонимы.
- Очередь сообщений не удаляется; после неопределённого результата доставки повтор не выполняется автоматически.

**Проверки:** тесты отправки в существующий и новый чат, защита от двойного создания, повтор после отказов, идемпотентное ACK, Unicode/UTF-8, WinForms, Router Lite, передача файлов.

**Открытый критерий приёмки:** подтверждение `ui/message` ещё не доказывает, что новый диалог открыт в обычном ChatGPT, а не Work. После установки нужна визуальная проверка режима и двух последовательных ответов в одном чате. Минимальная метка возврата ответа пока видна в облачной переписке; скрытого host-канала для этой метки в данной реализации нет.
