# v0.2.20 — адаптация Global/Thread MCP Apps под обычный ChatGPT

Дата: 2026-10-29.

## Реальное наблюдение на DOMKAT

В v0.2.19 tools/list возвращал chat.hub.open и chat.thread.open как app-only, с соответствующими Global/Thread entrypoints. После обновления инструментов обычный ChatGPT в настройках показал предупреждение: «Для этих приватных инструментов невозможно отобразить виджеты: chat.hub.open, chat.thread.open». Браузер и сервер загрузили оба ui:// ресурса, но tool-open и ui-initialize ни одного не последовали. Это не отказ спецификации: в конкретной сборке хоста наш путь app-only не создаёт виджет. В v0.2.18 интерфейс открывался со visibility=model+app.

## Исправление

- Для chat.hub.open и chat.thread.open установлено visibility=["model","app"], чтобы они могли быть запущены в обычном ChatGPT и как entrypoint, и через model-invoked tool.
- Разделены статические точки входа: chat.hub.open имеет только Global, chat.thread.open имеет только Thread.
- У старого chat.ui.open удалена исключительно метаинформация о глобальном/внутридиалоговом входе; инструмент продолжает работать по прежнему имени и принимает chat_id. Старый HTML-ресурс relay-v0218 и система очередей не затронуты.
- Для двух диагностических ресурсов новые URI lifecycle-global-v0220 и lifecycle-thread-v0220 во избежание использования кэша старого HTML.
- Актуализированы контрактные тесты, версия и GitHub Actions.

## Приёмка

Проверить в обычном ChatGPT:
1) В настройках плагина исчезает предупреждение о «приватных инструментах, для которых невозможно отобразить виджеты».
2) По «Открыть плагин» запускается Global Hub с новым URI.
3) На сервере в lifecycle-probe/events.jsonl появляются tool-open, resource-read, ui-initialize, ui-initialized и heartbeat для mode=global.
4) В отдельном ChatGPT-диалоге вручную открывается thread entrypoint, его instance_id не совпадает с global.
5) Проверить действующий chat.ui.open(chat_id), что сообщения и ответы не смешиваются.
6) Проверить адресный OS-deep-link и последовательное закрытие тестовой вкладки (без принудительного завершения браузера с несохранённой пользовательской работой).

На этом этапе существующая 0.2.19 является промежуточным исследовательским выпуском; полностью поддерживаемая передача сообщений из v0.2.18 сохранена.
