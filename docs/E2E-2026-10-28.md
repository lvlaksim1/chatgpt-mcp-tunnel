# Проверка прямого вызова ChatGPT → Windows от 28.10.2026

## Зафиксированный результат

В ходе технического эксперимента в ChatGPT был зарегистрирован пользовательский MCP-плагин и проверен вызов `bridge_ping({})` через OpenAI Secure MCP Tunnel на Windows-компьютере `DOMKAT`.

Проверка показала:
- вызов из ChatGPT вернул ожидаемый маркер;
- локальный сервер на .NET 8 работал через `stdio`;
- официальный `tunnel-client` v0.0.18 оставался в состоянии `ready`;
- журнал Windows содержал событие `dispatcher forwarded command to MCP server` около 02:22 МСК;
- секретный ключ был сохранён в пользовательском DPAPI-хранилище и не публиковался.

Это доказывает работоспособность архитектуры ChatGPT → OpenAI Tunnel → Windows MCP, но **не** означает, что новая сборка этого отдельного репозитория уже испытана.

## Важное техническое замечание

Разборщик команды stdio клиента `tunnel-client` трактует обратные косые черты как экранирование. Поэтому путь к DLL в `mcp-command` на Windows должен передаваться с обычными прямыми косыми чертами, например `D:/ChatGPT-MCP-Tunnel/src/ChatGptMcpTunnel/bin/Release/net8.0/ChatGptMcpTunnel.dll`.

## Принцип независимости

Этот репозиторий не зависит от стороннего десктопного клиента, не использует текстовую вставку запросов в браузер, планировщик ChatGPT или внешний маршрутизатор пользовательских команд. Здесь собственный .NET MCP-сервер и собственный запускатель.
