# Прямое защищённое подключение удалённого компьютера через статический IP DOMKAT

Статус: реализовано в исходном коде для выпуска v0.2.8; испытания TLS и маршрутизации на одном компьютере пройдены. Реальное соединение DOMKAT–MKATUSHONOK через разные сети ещё не подтверждено.

## Схема

- ChatGPT → единственный существующий OpenAI MCP Tunnel → DOMKAT.
- У DOMKAT локальный адрес, например `192.168.0.3`, а статический публичный IPv4 назначен **WAN-интерфейсу домашнего маршрутизатора**, не сетевой карте Windows.
- Удалённый клиент из другой сети подключается к `wss://<публичный-IP-DOMKAT>:55202/agent` напрямую через Интернет.
- Маршрутизатор DOMKAT вручную перенаправляет **только внешний TCP 55202 → локальный адрес DOMKAT:55202**.
- Защищённый сервер Kestrel слушает на локальном сетевом интерфейсе; публичный адрес используется для формирования TLS-сертификата и адреса клиента, но не для привязки к сетевой карте.
- Прежний локальный WebSocket на TCP 55201 сохраняется для частных сетей и Tailscale, **в Интернет его перенаправлять нельзя**.
- Tailscale, VPS и иной сторонний сервер не требуются для прямого соединения. Для подключений за CG-NAT или если входящий порт заблокирован провайдером, нужен иной транспорт. Одно наблюдение публичного WAN IP не доказывает доступность входящих подключений.

## Настройка сервера (после установки обновления по решению владельца)

1. Открыть «Сервер → Настройки», оставить адрес маршрутизатора Router Lite равным **локальному адресу этого компьютера**; он должен быть назначен активному адаптеру (например, `192.168.0.3`).
2. Включить «Прямое защищённое подключение через Интернет (WSS)» и ввести **статический публичный IPv4 маршрутизатора** или своё доменное имя.
3. Сохранить настройки. Приложение создаст TLS-сертификат с отдельным приватным ключом; PFX-файл защищён случайным паролем, пароль зашифрован DPAPI текущего пользователя. Повторное сохранение с неизменным адресом не должно менять действительный сертификат.
4. После запуска в настройках нажать «Копировать отпечаток TLS-сертификата». Это SHA-256 от бинарного сертификата, 64 шестнадцатеричных символа. Передать клиенту по проверенному каналу, сверить независимо от подключения. При смене адреса/сертификата клиентам потребуется новый отпечаток.
5. По отдельному подтверждению нажать «Разрешить защищённый доступ из Интернета» и согласовать Windows UAC. Приложение создаёт узкое правило брандмауэра **для исполняемого модуля Router Lite, локального адреса и TCP 55202**. Общий ключ клиентов остаётся обязательным.
6. В интерфейсе своего маршрутизатора **вручную** настроить перенаправление TCP 55202 с WAN на локальный адрес DOMKAT, порт TCP 55202. Не включать UPnP автоматически ради этой функции и не перенаправлять TCP 55201.
7. Убедиться, что локальный адрес DOMKAT остаётся неизменным (например, через резервирование DHCP на маршрутизаторе), затем проверить подключение из **действительно иной** сети.

## Настройка удалённого клиента

1. Выбрать «Прямое защищённое подключение через Интернет (WSS)».
2. В поле «IP-адрес или имя сервера» ввести **публичный** адрес маршрутизатора DOMKAT; не вводить `192.168.0.3`, если клиент находится в другой LAN.
3. Ввести и сверить 64-символьный SHA-256 отпечаток сертификата сервера; приложение **не принимает** незнакомый/подменённый сертификат. Кнопка «Проверить» выполняет TLS-рукопожатие и проверяет отпечаток без передачи ключа.
4. Через отдельный временный диалог указать общий ключ подключения клиента. Он хранится в Windows DPAPI; в главном окне нет кнопки его раскрытия.
5. Сохранить и подключиться. Приложение автоматически формирует `wss://<адрес>:55202/agent`. При подключении использует шифрование TLS, закреплённый отпечаток и авторизацию ключом.

## Приёмка

- На **реальном** MKATUSHONOK проверить доступность TCP 55202 из иной сети, TLS-сертификат/отпечаток, успешное распознавание компьютера через `computers.list`.
- Выполнить удалённые `system.info`, чтение/запись тестового файла, PowerShell, снимок экрана и UI Automation, затем проверить восстановление подключения после перезапуска.
- Отрицательные случаи: неверный отпечаток, неверный ключ (401), дублирующееся имя (409), недоступность порта и завершение процесса.
- Зафиксировать результаты в капсуле менеджера. Публикация релиза или локальные испытания на одном компьютере не равны проверке через Интернет.

## Инварианты

- Единственный существующий OpenAI Tunnel ID, плагин ChatGPT и GitHub-инструменты сохраняются.
- Не сохранять приватный ключ/PFX, токены, DPAPI-файлы, публичный IP владельца или другую конфигурацию с секретами в Git.
- Релиз не открывает порт автоматически и не меняет сетевые настройки маршрутизатора.
- Самоподписанный TLS-сертификат безопасен против подмены **только при достоверной предварительной сверке отпечатка**. Не подтверждать клиенту неизвестный отпечаток без проверки.
