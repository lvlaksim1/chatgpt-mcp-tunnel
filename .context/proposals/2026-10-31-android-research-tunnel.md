## Существующая архитектура Tunnel

Исходники v0.2.65: активный чат — авторизованный chatgpt.com в ChatGptMainForm.cs (WebView2); старые ChatWindow.cs и WebViewChatHost.cs исключены из сборки. Темы и голос работают поверх WebView2. Зафиксированное отсутствие сетевых диагностических обработчиков в текущем ChatGptMcpAgent — возможность для отдельного пилота.
DOMKAT остаётся сервером с единственным официальным tunnel-client и Happ; MKATUSHONOK — Router Lite клиент с Free Xray для своего WebView2, без второго tunnel-client и без Happ. Единственный авторизованный профиль WebView2 сохраняется.

## Рекомендуемые этапы

**P0 — пассивная диагностика запросов WebView2.** Исследовать WebResourceResponseReceived и при необходимости события Network.* через Chromium DevTools Protocol. Начать с локальной синтетической страницы; затем с разрешённого безопасного чата. Диагностика по умолчанию выключена. Записывать только время, локальный ID операции, категорию очищенного URL, HTTP method/status, этап и длительность. Не сохранять пользовательский текст, тело, cookies, заголовки, токены, идентификаторы аккаунтов, исходный URL с query/fragment. Не изменять и не повторять HTTP-запросы. Событие responseReceived не доказывает окончание SSE/генерации. Отключение диагностики должно не менять сайт или прокси.
**P1 — автомат состояний сообщения.** draft, submit_requested, submission_observed, response_started, response_streaming, response_completed; альтернативы cancelled, network_failed, result_unknown. Связь с активной вкладкой и облачным диалогом, корреляция локальным operation_id, идемпотентность, запрет слепого повторного отправления при неизвестном результате. DOM остаётся источником текста; сетевые события — дополнительными фактами.
**P2 — интеграция с голосом.** Передавать только законченные неповторяющиеся фрагменты текста в текущий Sherpa-ONNX TTS. Проверить смену вкладки, перезагрузку, остановку, прерывание озвучки и отсутствие дублей.
**P3 — VPN/сеть.** Обработка разрыва и переподключения без повторной отправки сообщения; сохранить существующие правила DOMKAT/MKATUSHONOK, один авторизованный профиль, один MCP tunnel-client на сервере и актуальные механизмы резервирования.

## Приёмка и ограничения

- P0: проверка на тестовой странице и безопасном диалоге, отсутствие секретов в журналах, сохранение авторизации/вкладок/профиля/MCP.
- P1/P2: 2/2, затем 10/10 последовательных сообщений без дубликатов в одном обычном чате; отмена, смена вкладки, переподключение, корректное озвучивание.
- P3: изолированный сетевой сбой, восстановление без повторного запроса с неизвестным результатом и без замены действующих MCP-процессов.
- Никакого отдельного OpenAI API, Work/Codex, второго профиля или туннеля; без GitHub Actions и prerelease. UI/CSS сначала проверять в живом WebView2, изменения .NET-хоста выпускать только контролируемой сборкой с откатом.
- Не предлагать замену браузера прямым HTTP-клиентом как уже доказанный вариант: мобильный и Windows транспорты различаются.
