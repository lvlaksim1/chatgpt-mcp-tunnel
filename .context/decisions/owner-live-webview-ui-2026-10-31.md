# Решение владельца: изменение интерфейса ChatGPT в работающем WebView2 — 31.10.2026

Идентификатор: OWNER-LIVE-WEBVIEW-UI-2026-10-31. Статус: обязательное действующее правило разработки ChatGPT MCP Tunnel.

1. Любые изменения внешнего вида и поведения веб-интерфейса ChatGPT (CSS, JavaScript, расположение кнопок, меню, DOM, обработчики действий) **сначала** вносить непосредственно в уже запущенный WebView2 Tunnel, без пересборки, переустановки и перезапуска приложения, когда это технически осуществимо.
2. Использовать динамическую загрузку пользовательских файлов `Themes\ChatGPT-Warm-Dark.css` и `Themes\ChatGPT-Toolbar.js` и применение в действующий документ WebView2; для временных экспериментов допустима инъекция через `CoreWebView2.ExecuteScriptAsync` или доступный канал исполнения команд в существующей странице. Не открывать для каждой правки отдельный браузер.
3. После каждого изменения **проверить результат в том же открытом окне**: визуально, интерактивно и на сохранность штатных функций ChatGPT (создание и продолжение чатов, ввод, отправка, меню, обмен ссылками, вложения). Исправлять до подтверждённого результата. Одного успешного теста синтаксиса или компиляции недостаточно.
4. Только после проверки перенести окончательный вариант в файлы исходников/темы, сохранить в Git и включить в будущую сборку. Переустановку не использовать как обычный цикл CSS/JS-правок.
5. Если конкретное изменение требует C#/.NET, WebView2-хоста, установщика, прав Windows или иного кода, недоступного для горячего обновления, сначала объяснить причину и провести единый минимально необходимый выпуск после проверки доступных способов реализации без перезапуска.
6. Сохранять текущие авторизацию, открытый диалог, пользовательские данные и состояние Tunnel. Не выдавать непроверенную визуализацию или тестовый макет за подтверждение работоспособности основного WebView2.
7. Не считать ненайденную штатную функцию WebView2/DOM доказательством невозможности задачи: изучать API и проверять реализацию экспериментально. Цели и окончательные требования задаёт владелец.

Это процедурное правило действует для всех последующих задач по интерфейсу, пока владелец не изменит его. Оно не является разрешением на установку новых версий без соответствующего запроса и не отменяет правила безопасности/STOP.
