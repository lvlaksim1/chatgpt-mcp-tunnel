# Manager goals

## ПРИОРИТЕТНЫЙ СТРАТЕГИЧЕСКИЙ МАНДАТ — 30.10.2026: цели всего MCP Tunnel
Подтверждено владельцем в текущей беседе. ChatGPT MCP Tunnel — НЕ просто инструмент управления Windows и НЕ только чат. Это единая автономная инфраструктура взаимодействия человека, ИИ и всех его компьютеров. ChatGPT — один из участников системы, а не единственный интеллект или фундамент архитектуры.

### Семь долгосрочных целей
1. Полноценное исполнение задач ИИ на Windows через MCP: файлы, процессы, shell/PowerShell, UI Automation, приложения, Git/GitHub, многошаговые рабочие сценарии, просмотр состояния, безопасное исправление проблем, отчёт о результате.
2. Объединение сколь угодно многих принадлежащих пользователю компьютеров вне зависимости от локальных сетей: одновременное подключение, адресное выполнение, переключение между машинами и передача больших файлов с прогрессом; DOMKAT и MKATUSHONOK — текущие участники.
3. Равноправие и автономность каждого компьютерного узла: в целевой архитектуре нет единственного обязательного главного ПК; любой узел независим, но сохраняет возможность находить другие узлы, взаимодействовать и работать при их отключении. Это ДОЛГОСРОЧНАЯ ЦЕЛЬ, не объявлять внедрённой в Router Lite.
4. Двусторонний локальный чат как полноценный мессенджер: пользователь только пишет/читает; отдельные новые и прежние диалоги с контекстом, автоматическая доставка и восстановление без ручных вызовов ретранслятора. Обмен с ChatGPT — через MCP; WebView2 только авторизация. Конкретная приёмка чата — 10 последовательных сообщений/10 ответов без действий пользователя, плюс новые/существующие чаты, restart и несколько ПК.
5. Своя голосовая связь с моделью: бесплатные независимые автономные модули распознавания речи и синтеза голоса, встроенные в общую систему; не полагаться на голосовой интерфейс ChatGPT. Это ПЛАН, не завершённый функционал.
6. Универсальность MCP как стандарта для разных LLM и агентов: ChatGPT, локальные Ollama/Goose и иные совместимые модели должны пользоваться общими инструментами и узлами, без жёсткой зависимости архитектуры от конкретной модели. Это ЦЕЛЬ совместимости, не текущая подтверждённая многомодельная приёмка.
7. Максимальная самостоятельность и безопасность: минимум внешних платных или контролируемых третьими сторонами зависимостей, независимые бесплатные компоненты, изоляция доступа к пользовательским компьютерам, локальный контроль разрешений и STOP, автоматический запуск и самовосстановление, сохранение авторизаций и автообновления.

### Обязательные инженерные ограничения владельца
- Один продукт / один MCP Tunnel, без множества новых туннелей под каждую функцию; русский интерфейс по возможности.
- Windows 10 сохраняется; Windows 11 не предлагать.
- Активный системный VPN Happ не отключать. Независимость от платного Happ — СТРАТЕГИЧЕСКОЕ НАПРАВЛЕНИЕ, не уже достигнутое состояние.
- Для ChatGPT использовать обычный режим Чат по существующей подписке, без отдельного API, Work или Codex для транспорта сообщений; никакого DOM-сценария отправки сообщений.
- Локальная разработка/сборка/испытания на DOMKAT; GitHub только исходники и готовые Releases, Actions не запускать.
- Разделять завершённые возможности, частичные прототипы и планы; проверять на практике вместо поспешных выводов о невозможности. Текущий приоритет P0 — надёжный автономный MCP-чат, но он не заменяет перечисленных семи целей.


## ГЛАВНАЯ ЦЕЛЬ — полностью автоматический MCP-чат, 30.10.2026
- Локальное окно должно работать как мессенджер: пользователь только пишет и получает ответы, не запускает chat.ui.open, не нажимает «Начать передачу», не ищет и не поддерживает MCP Apps.
- «+ Новый чат» — новый диалог в обычном ChatGPT; прежний локальный чат продолжает точно соответствующий ему облачный диалог без потери контекста и дублей.
- Обязательная приёмка: 10 последовательных сообщений и 10 правильных ответов в одном локальном чате; затем существующий/новый чат, перезапуск, разрыв и несколько компьютеров.
- Только MCP-обмен сообщениями и chat.reply, WebView2 только авторизация. Исключить DOM-ввод, браузерные клики и чтение ответов, Node/CDP, отдельный API, Work/Codex.
- Сохранить Windows 10, VPN Happ, один туннель, Router Lite, безопасную очередь и локальный STOP. GitHub только код и готовые Releases, Actions не использовать.

## Актуальные цели — 30.10.2026

- Быстрая работа: вначале цельный план, затем один локальный сценарий правок, сборки, проверок и краткий результат, вместо десятков микрозапросов.
- Безопасное управление: локальный STOP, содержательные уведомления без секретов, ~1 сек между изменениями GUI, без искусственных задержек CLI; различение выполнения/ожидания модели/достоверного завершения.
- Только локальная разработка и тестирование на `D:\Dev`; GitHub — место хранения исходников и готовых релизов, **Actions отключены**.
